## Documentation check

```powershell
.venv/Scripts/python scripts/validate_preparation.py
```

The script modifies no document and calls neither the network nor a model. The `--root` option checks a copy of the repository. Exit codes: 0, structural checks passed; 1, failure; 2, missing dependency.

It checks the presence of the files, UTF-8, local Markdown links, the specification digest, the coverage of the F/I/N/T/X identifiers, the 14 tickets and their acyclic dependencies, the meta-schemas, the examples and the structural refusals. The date check is explicitly enabled. It parses the YAML and checks that the business test namespace is distinct from T-17. It also characterizes three schema limits: fictitious evidence, a duplicated `read_set` and a past deadline can stay syntactically admissible. These constraints require the kernel's semantic checks. The count includes links and structural items; it is not a count of behavior tests.

During the initial preparation, the global Python lacked `rfc3339-validator`: the negative check detected that invalid dates were accepted. The dependency is now part of the locked environment and invalid dates are refused. Three errors introduced into a temporary copy (missing local link, dependency cycle, invalid proposal date) were detected with exit code 1.
